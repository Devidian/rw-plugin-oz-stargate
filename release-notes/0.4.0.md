# OZ - Stargate 0.4.0

- A ten-second travel tunnel covers local journeys and starts anew when a player arrives from another server. Players can disable it in personal settings; arrival sound and visibility wait until arrival is complete.
- A player's first regular visit to a server can arrive through an available gate. Incoming transfers and later logins are excluded.
- Entering a DHD chunk discovers its address. The personal address book follows the player across connected servers; known local destinations remain available if the relay is unavailable. The DHD also accepts a manual gate ID and distinguishes local from remote destinations by border color.
- The DHD can start a Discovery attempt after a five-minute cooldown. Success chance and search radius are configurable. After seven chevrons, a successful attempt creates a gate with DHD at a checked site and teaches its address to the discovering player.
- A fresh installation searches the global spawn sector for a suitable first gate and DHD. Existing installations do not add one automatically.

Requires **OZ Tools 0.26.2** and Rising World Unity with PluginAPI 0.9.3.2. Cross-server travel and shared address books require **OZ Stargate Network 0.4.0**; `network.enabled` remains off by default. Back up world, native player and plugin databases, finish active transfers, and upgrade the relay before the plugin. Existing address books start empty; players discover gate addresses at DHDs. Roll back plugin and relay together only after resolving in-flight transfers, keeping database backups paired. The known visitor-inventory limitation after a manual server switch remains.

Discovery placement checks terrain height and clearance from server-side chunk data. As accepted on Development, a first gate can still leave a newly arrived player with fall damage, and a DHD can sit slightly in the ground; placement should be checked before relying on it in a live world. The hosted test relay is not opened to the public.
