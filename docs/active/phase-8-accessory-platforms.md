# Phase 8: Accessory Pack gate platforms

## Objective

Add the four supplied Accessory Pack 1 platforms as selectable gate-and-platform placements under a `Plattformen` radial submenu. The floor point under the admin's crosshair anchors the platform; the gate and aligned arrival sit on its authored central deck. Existing gate and DHD placement commands remain compatible.

## Constraints and ownership

- `rw-plugin-oz-stargate` owns the menu, local placement, persistence, rendering and assets. No relay or Production change.
- Supplied files remain under `S:/Stargate/Stargate_2020_Accessory_Pack_1`; package only derived runtime assets. Review source distribution rights before a public release.
- Preserve the current gate ID, sector, horizon, DHD and transfer contracts. Existing visual rows mean no platform; an additive schema migration must leave them intact.
- Keep Unity 6000.3.22f1 and Windows/Linux/macOS bundles. The platform must have walkable collision without blocking the gate aperture.
- The four sources are `Circular_Platform` (14,435 triangles), `CurvedBase_MilkyWay` (244,058), `CurvedBase_Pegasus` (242,670) and `Grace_of_God_Platform` (47,570). Source coordinates are metres with Y up. The circular central deck is 0.444 m high, both curved decks are 1.333 m high, and Grace of God is about 0.44 m high near its origin. Verify exact gate registration height against the runtime mesh.

## Implementation checklist

- [x] Inspect model orientation, origin, materials and collision footprint; choose reproducible derived bundle inputs and record hashes.
- [x] Build four platform prefabs with render LODs and walkable colliders; verify three-platform bundle structure. Client material compatibility remains a player check.
- [x] Add an optional platform type to gate visual persistence and migrate old rows without moving existing gates. Deletion and relocation deliberately clear the platform when using plain gate placement.
- [x] Attach the selected platform to the gate visual lifecycle and keep the gate visible if a saved platform bundle fails to load.
- [x] Add `Plattformen` radial submenu and DE/EN labels. Each variant aims at a floor point, checks sector, overhead clearance and passage overlap, then atomically places the gate and platform.
- [x] Validate Java 25 package and persistence/placement tests; upload to Development only after bundle and package checks.
- [ ] Player-check each platform variant for facing, scale, terrain anchoring, gate passage, collision, LOD and DHD compatibility. Measure bundle transfer and client frame cost before accepting default use.

## Risks and rollback

The curved sources are high polygon meshes, so LOD and bundle transfer cost need a client check. A wrong platform deck height can embed the gate or spawn arriving players below its floor. Keep existing plain gate placement available. To roll back, first move any platform gate to safe terrain with the plain gate action. Back up the SQLite database, then remove the nullable `platform_type` column from `stargate_visuals` before restoring the old plugin/bundle: the old store uses a positional six-column `INSERT` and cannot save into the expanded table. The new build reads old six-column rows and performs the forward migration automatically.
